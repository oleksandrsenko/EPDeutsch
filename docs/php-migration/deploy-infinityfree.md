# Развёртывание на InfinityFree: пошагово

Всё ниже проверено локально (php -S + MariaDB 10.11), **на самом InfinityFree эта версия не запускалась**. Места, где я не уверен в интерфейсе хостинга, помечены «проверь».

## 0. Что понадобится

- аккаунт на infinityfree.com и созданный хостинг-аккаунт (с поддоменом или своим доменом, SSL включить в панели);
- этот репозиторий (ветка `agent/php-infinityfree`);
- на своём компьютере PHP 8+ (`brew install php`): нужен для сборки дампа данных и секрета;
- ключи, если нужен ИИ: Anthropic, OpenAI, DeepL — те же, что лежат в `db/anthropic.key`, `db/openai.key`, `db/deepl.key`. **В git и на хостинг через почту/чат их не отправляй**, вписываешь вручную в шаге 5.

## 1. Подготовить данные локально (один раз)

Из корня репозитория, **исходная база остаётся нетронутой** (скрипт открывает её только на чтение; для надёжности сначала сделай копию):

```bash
sqlite3 -readonly db/unisicher.db ".backup '/tmp/epd-copy.db'"
php scripts/migrate_sqlite_to_php.php --sqlite=/tmp/epd-copy.db --dump=/tmp/epd-data.sql.gz
```

В конце скрипт печатает таблицу «строк в SQLite / записано» и `ИТОГ: всё сошлось`. Файл `epd-data.sql.gz` содержит хеши паролей: это секрет, не публикуй и после импорта удали.

Секретная строка для подписи ссылок и соли посетителей:

```bash
php -r 'echo bin2hex(random_bytes(32)), "\n";'
```

Сохрани результат, он понадобится в шаге 5.

## 2. Создать базу MySQL

В панели хостинга: **MySQL Databases** → создай базу (например `epd`). Панель покажет и сохрани (проверь названия полей в панели):
- хост вида `sqlXXX.infinityfree.com` (это не `localhost`);
- имя базы вида `if0_12345678_epd`;
- имя пользователя `if0_12345678` и пароль от аккаунта.

К этой базе можно подключиться только с самого хостинга. С компьютера напрямую нельзя, поэтому данные идут через дамп и phpMyAdmin.

## 3. Импортировать схему и данные (phpMyAdmin)

1. В панели нажми **phpMyAdmin** рядом с базой и выбери её слева.
2. **Импорт** → выбери файл `schema/mysql.sql` → выполнить. Должны появиться таблицы (users, sessions, progress, … audit_log, rate_limit).
   - В конце файла триггеры защиты владельца (`owner_no_delete`, `owner_keep_role`). Если у бесплатного тарифа нет права `TRIGGER`, phpMyAdmin покажет ошибку именно на них: таблицы к этому моменту уже созданы, ничего страшного. Те же проверки есть в PHP-коде.
3. **Импорт** → `epd-data.sql.gz` (phpMyAdmin принимает `.gz`; если не примет, распакуй `gunzip` и загрузи `.sql`). Размер сейчас около 13 КБ.
4. В конце дампа лежит запрос сверки: скопируй из распакованного файла блок после комментария «Сверка» (`SELECT 'users' AS tbl, 6 AS expected, ...`) и выполни на вкладке **SQL**. В каждой строке `expected` и `actual` должны совпасть.
5. Удали `epd-data.sql.gz` с компьютера, если не нужен.

Чистая установка без переноса: просто пропусти шаги 3.3–3.5 (данные), схему (шаг 3.2) импортируй обязательно.

## 4. Загрузить файлы (FTP или Online File Manager)

Рекомендую FTP (FileZilla): данные для входа есть в панели хостинга (FTP Details). Проверь, что можно создавать папки рядом с `htdocs`.

**Вариант А (лучший): папки рядом с `htdocs`**

```
/ (корень FTP)
├── htdocs/        ← сюда всё содержимое папки public/ из репозитория (index.php, .htaccess, *.html, ep.js, data/, schreiben/, mail/, иконки, пустая audio/)
├── app/           ← папка app/ целиком (в ней .htaccess и prompts/)
├── config/        ← config.example.php и .htaccess (config.local.php создашь в шаге 5)
└── storage/       ← пустая папка storage/ с .htaccess и cache/
```

**Вариант Б: если рядом с `htdocs` создавать нельзя**, положи всё внутрь `htdocs/`: `htdocs/app`, `htdocs/config`, `htdocs/storage` вместе с содержимым `public/`. `.htaccess` в этих папках закрывает их от браузера (код сам находит `app` и в `../app`, и в `./app`).

**Не загружай:** `db/`, `*.key`, `server.py`, `lernen_api.py`, `tools/`, `src/`, `data/*.json` (это исходники словаря, нужны только скриптам), `.git`, `.claude`, `scripts/` (миграция идёт с компьютера), `docs/`.

Права: папки `htdocs/audio` и `storage` (и `storage/cache`) должны быть доступны на запись (обычно по умолчанию 755 хватает; если сайт жалуется на запись, поставь 775 в FTP-клиенте).

Если у тебя уже есть сгенерированное аудио (`db/audio/*.mp3`), положи файлы в `htdocs/audio/`. Сейчас в боевой базе аудио-кэш пуст.

## 5. Заполнить `config/config.local.php`

Скопируй `config/config.example.php` в `config/config.local.php` (через FTP: скачать, переименовать, загрузить) и впиши значения:

```php
<?php
return [
    'db' => ['host' => 'sqlXXX.infinityfree.com', 'port' => 3306, 'name' => 'if0_12345678_epd', 'user' => 'if0_12345678', 'pass' => '…'],
    'secret' => '…64 символа из шага 1…',
    'site_url' => 'https://твой-домен',          // без / в конце
    'owner_emails' => ['твоя@почта'],            // кто станет владельцем, если владельца в базе ещё нет
    'anthropic_key' => '', 'openai_key' => '', 'deepl_key' => '',   // впиши вручную из db/*.key
    // дальше можно оставить по умолчанию
];
```

Файл `config.local.php` в git не попадает (он в `.gitignore`). Ключи нигде, кроме этого файла на хостинге, не хранятся: в админке значения ключей не показываются, а кнопка «записать ключ» в настройках отвечает, что ключи задаются в этом файле.

## 6. Проверить, что всё запустилось

1. Открой `https://твой-домен/api/regopen`: должно быть `{"open":false}` (если ты импортировал данные) или `{"open":true}` (чистая установка). Ошибка про базу значит неверные данные в `config.local.php`.
2. Открой `https://твой-домен/` и войди (шаг 7).
3. Войдя владельцем, открой `https://твой-домен/api/admin/diag?net=1`. Там версия PHP, нужные расширения (`curl`, `pdo_mysql`, `mbstring`, `sodium`), `argon2id`, `max_execution_time`, `post_max_size`, **видимый IP** посетителя и достижимость внешних сервисов (Anthropic, OpenAI, DeepL, MyMemory, LanguageTool, Wiktionary). Что нужно проверить:
   - `curl: true`, иначе ИИ и переводы не работают;
   - `argon2id: false` не страшно, будет bcrypt; если вход тормозит или падает на нехватке памяти, поставь `'password_algo' => 'bcrypt'`;
   - `max_execution_time`: если там 30 или меньше, оставь `ai_timeout` ≤ 25;
   - `ip_used`: должен быть IP посетителя, а не адрес прокси хостинга. Если везде одинаковый, поставь в конфиге `'ip_header' => 'HTTP_X_FORWARDED_FOR'` (или `HTTP_CF_CONNECTING_IP`), иначе лимит регистраций с одного IP будет общим на всех;
   - блок `net`: у сервисов, к которым хостинг не достучался, будет `ok: false`.

## 7. Первый владелец

- **После переноса данных** владелец уже есть (твоя прежняя учётка). Войди тем же паролем, что был на старом сайте: старый PBKDF2-хеш проверится прежним алгоритмом, а при успешном входе сразу заменится на Argon2id/bcrypt.
- **Чистая установка:** пока в базе нет ни одного пользователя, регистрация открыта. Зарегистрируйся первым через форму на главной: этот аккаунт станет владельцем (если в `owner_emails` указана почта и вы регистрируетесь с ней, то владелец именно она). Дальше регистрация только по приглашениям: Настройки → Приглашения.
- **Аварийно (забыл пароль владельца).** Писем нет, поэтому через phpMyAdmin. На компьютере получи хеш: `php -r 'echo password_hash("ВременныйПароль-1", PASSWORD_BCRYPT), "\n";'`, потом на вкладке SQL:
  ```sql
  UPDATE users SET pw='ТУТ_ХЕШ', must_change_password=1 WHERE role='owner';
  DELETE FROM sessions WHERE user_id=(SELECT id FROM (SELECT id FROM users WHERE role='owner') t);
  ```
  Войдёшь с временным паролем, сайт сразу попросит придумать новый.

Забывшим пароль обычным пользователям временный пароль выдаёт админ: Админ-панель → пользователь → «Сбросить пароль» (пароль показывается один раз, пользователь обязан сменить его при входе; всё пишется в журнал).

## 8. После запуска

- Создай приглашения для друзей: Настройки → Приглашения.
- Проверь ИИ: Schreiben → проверка текста; Практика; озвучка Hören. Если проверка Schreiben упирается в время (ошибка «ИИ не успел ответить»), в `config.local.php` поставь `'grade_effort' => 'low'`, уменьши `grade_max_tokens` (например 4000) или проверяй тексты короче.
- Озвучка сценариев Hören идёт по частям (за один запрос не больше `audio_budget` секунд); страница сама повторяет запрос, готовые реплики кэшируются.
- Посмотри `https://твой-домен/admin`: сводка, пользователи, журнал действий.
- Бэкап: phpMyAdmin → Экспорт → SQL. Делай периодически: бесплатный хостинг бэкапов не гарантирует.

## 9. Ограничения бесплатного тарифа, которые важны

- **Нет cron.** Чистка (просроченные сессии, старые посещения и кэш ИИ, итоги забегов) выполняется «лениво» при обычных запросах, не чаще раза в час.
- **Нет писем.** Подтверждения почты и восстановления пароля по ссылке нет; рассылка и напоминания не работают. Ссылки отписки из старых писем остаются рабочими.
- **Защита от ботов у хостинга.** Запросы без браузера (curl, uptime-мониторы) хостинг может отбивать проверкой на JavaScript. Из браузера всё работает. Если захочешь мониторинг доступности, проверь, пропускает ли он ваш `/api/regopen`.
- **Лимиты хитов и ресурсов.** При большом числе запросов хостинг может притормаживать сайт. Для двух-трёх человек хватает.
- **Время запроса к ИИ ограничено** (см. `ai_timeout`); самый тяжёлый запрос это проверка текста в Schreiben и разбор речи в Sprechen.

## 10. Если что-то не работает

| Симптом | Что смотреть |
|---|---|
| «Нет связи с базой данных» | хост (`sqlXXX.infinityfree.com`, не `localhost`), имя базы с префиксом `if0_…`, пароль |
| Белая страница или 500 | в `config.local.php` поставь `'debug' => true` на время, открой `/api/me`: ошибка покажется в ответе. Потом верни `false` |
| Кабинет открывается, а аудио/кэш не пишется | права на `htdocs/audio` и `storage` |
| Все посетители «с одного IP», регистрация блокируется | `ip_header` в конфиге (шаг 6) |
| Не входит старым паролем | в базе должен быть хеш вида `соль$хеш` (97 символов), как перенёс скрипт; проверь, что импортирован дамп данных |
| ИИ молчит | `/api/admin/diag?net=1`: ключи (`keys`), `curl`, доступность сервисов |
